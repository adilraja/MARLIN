# Bounded proposal for Gate A

Status: **proposed; not implemented**. Review together with the audit, capture contract, acceptance plan and complete capture declaration. Existing behavioural, animation, ocean, asset and water acceptance boundaries remain in force.

## M2 feasibility stop before implementation expansion

1. Begin only after named Gate A acceptance. Recheck host state/resources and checkpoint any newly running live scene before mutations; do not restore an old scene over newer work.
2. Use an isolated finite Kit profile/app and supported extension-manager metadata to determine whether native instance/semantic annotation can be provided by already installed components compatible with Kit 110.2.0. Do not enable a provider in the user's normal installation as a discovery shortcut. The M1 inventory did not register Replicator or SyntheticData.
3. If new packages are necessary, **stop before installing**. Prepare exact official package/version, dependency graph, compatibility evidence, disk estimate, isolated destination, source/preset preservation pins and rollback. Return for concrete review. Gate A is not approval of a broad reinstall, upgrade, generated-file inspection or unknown dependency choice. A documentation version number is not a compatible package pin.
4. Demonstrate bounded startup and clean exit before any rendered acceptance capture. The M1 query returned data but required timeout cleanup; do not count that as a clean lifecycle. Avoid the unrelated importer/converter path in the finite diagnostic app rather than repairing vendor files. Retain all failed attempts. No runtime replacement or driver change is proposed.

## Numeric acceptance and workload

The JSON [acceptance plan](../contracts/acceptance_plan.json) is authoritative for proposed thresholds. Examples: ≤1 px dry camera/box error; zero incorrect unambiguous dry interior pixels outside the 1 px boundary band; zero stale/mixed-time bundles; accepted root/joint/skin/phase replay limits; ≥0.995 remapped mask repeat IoU; and separately tested HDR/display repeat limits. Marine manual comparisons require confident foreground, explicit uncertainty, ≤20% uncertain foreground support and ≤2% missed/false confident body pixels under the declared denominators. Ambiguous positives cannot be promoted to qualified masks.

The primary matrix has 60 rows; M3's 21 sentinel rows and 12 review rows are explicit ID lists. Twelve repeat/reload primary references are fixed. Capture-order, source family, identity renumbering and absence-counterpart relations are retained. No train/test split is created.

## Failure and rollback

Keep failures under distinct attempt IDs. Refuse nonfinite data, missing mappings, wrong products, time drift, out-of-budget resources and duplicate owners. Freeze on missing state rather than activating an autonomous fallback. Do not relax limits after seeing a failure. Stop the dependent block and propose an amendment or dependency remedy at the applicable gate.

Restore only the **newly recorded pre-work** scene/settings/controllers, detach owned annotators, destroy the one owned product, remove temporary labels/layers and verify recovery. Never delete or overwrite accepted evidence. See [reproduction and rollback](../REPRODUCTION_AND_ROLLBACK.md).
